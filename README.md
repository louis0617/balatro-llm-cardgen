# balatro-llm-cardgen

An LLM writes Balatro joker effects as executable Python, and the generated code is checked in several layers before it is played in a headless simulator.

## Overview

Given a short natural-language design intent, the model writes a function of the form:

```python
def effect(ctx, hand_type, scored_cards, played_cards, held_cards, game, joker):
    ...
```

The function can write to `ctx.mult`, `ctx.chips`, `ctx.x_mult`, `ctx.dollars` and `ctx.retrigger_count`, read the current hand and game state, and optionally define `on_discard(...)`. The allowed surface is defined in `cardgen/effects/effect_runtime.py`, and the prompt that describes it to the model is in `cardgen/prompts/effect_prompt.txt`.

## How generated code is checked

```mermaid
flowchart LR
  A[Design intent] --> B[LLM-written effect]
  B --> C[Sandbox AST]
  C --> D[Behavioral AST]
  D --> E[Smoke cases]
  E --> F[MiniBalatro + greedy agent]
```

1. **Sandbox AST** (`effect_runtime.ast_validate`). No imports or dunder access, only calls listed in `ALLOWED_CALLS`, and only `effect` and `on_discard` may be defined.
2. **Behavioral AST** (`ast_constraint_checker.check_behavioral_constraints`). Checks that the code matches the intent it was written for. Intents not labeled as economy cards may not rely mainly on money or heavy discard effects, and `lock` intents may not decrease `mult`, `chips` or `x_mult`.
3. **Smoke cases**. Fixed hands, money and discard setups confirm that each effect compiles and runs without errors.
4. **Simulation**. Effects are attached to MiniBalatro (`cardgen/engine/game.py`, `interpreter.py`) and played by a greedy agent.

A note on rule design. Structural rules, such as requiring a minimum number of branches for intents that should open up new strategies, are intentionally not used. The model tends to satisfy such rules with trivial branches that pass the check without changing how the card plays, so passing the rule says little about the design itself.

## Quick start

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
pip install -r requirements.txt
python examples/run_smoke_on_examples.py
```

Run a simulated game with the greedy agent, and the tests:

```bash
python examples/run_minibalatro_greedy.py
pytest -q
```

## Examples

`examples/cards/` contains five cards generated by the model. Each file includes the design intent, the generated code and its check results.

## Repository structure

```text
cardgen/effects/    effect runtime, AST checks, joker interpreter
cardgen/engine/     MiniBalatro simulator
cardgen/agents/     greedy agent, behavioral cloning agent
cardgen/prompts/    generation prompt
examples/cards/     generated example cards
examples/           smoke and simulation demos
scripts/            SMODS export for template-based jokers
tests/              scoring and simulation tests
```

## Notes

- The behavioral cloning agent was trained on gameplay logs from study participants, so its weights are not included. Without them the agent falls back to the greedy policy.
- Shop archetype weights are not included. The greedy agent runs with neutral shop weights, and hand play and discards are unaffected.
- `scripts/export_new_joker_pack.py` writes Steamodded Lua for whitelist-template jokers. It does not translate Python `effect()` functions into Lua.
- No game files or assets are included.
